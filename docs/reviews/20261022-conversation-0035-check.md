## 已修复的重点问题

1. 独立辅助调用原先用了需要图协议绑定的工厂入口；改为 `get_chat_model()`，经本机兼容 Provider 实际调用。
2. 摘要轮询提前写 ready 触发 effect 清理，迟到读取结果被丢弃；现在先读取摘要再更新任务状态，有前端回归。
3. 展示时间重复把秒转毫秒；统一使用服务端格式化函数，实际页面显示 2026 年。
4. 最近七天使用滚动窗口；改为今天及前六个自然日，有跨夏令时测试。
5. 失败摘要的去重任务无法主动重试；显式请求可重新排队，后台轮询不无限重试。
6. 独立归档结束/恢复后的编辑缺少可靠 dirty 交付；增加持久 outbox、单调来源版本与提交前校验。修订已覆盖消息时，清除旧派生概览/语义事件/摘要缓存，重新读取原文。
7. PostgreSQL 生成提交增加账号、会话和元信息行锁；账号/会话使用 `FOR NO KEY UPDATE`，允许来源事务的外键检查。实际 PostgreSQL 并发测试仍未执行。
8. 一个既有工作模式测试依赖 Windows 墙钟的时间精度；改为受控时钟保证旧回执、修复报告与新验证顺序，不更改生产工作模式逻辑。
9. 补齐验证步骤与回执支持的独立计数，工作流版本推进也触发元信息更新；分叉以当前子会话中的事实事件记录来源，不复制未来事实和验收。
10. 获授权的真实 OpenCode 烟测暴露可选推理占用输出预算；复用已有 reasoning adapter 与 JSON 调用助手，关闭可选推理，保持原预算与超时。真实调用及引用校验通过。模型仍可能误分类语义条目，因此模型阻塞文字只作为线索，不能自动改变工作状态；增加回归。
