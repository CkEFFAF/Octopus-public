# 流程 Graph

流程 Graph 把执行、评估、分析和改进保存为可重复运行的流程。用户在画布编辑，Agent 用工具编辑，二者使用同一份定义、版本和权限规则。

## 编辑与运行

打开项目中的“流程 Graph”。左上角流程名称用于切换和新建流程。画布占满工作区，添加节点在画布左上角；点击节点才展开配置面板，底部“运行记录”按需展开。

保存、发布、启动、导入、导出、撤销、重做、预算、定时配置和事件入口统一放在右上角“流程设置”。保存更新草稿；发布生成不可变版本；启动运行最近发布的版本。修改草稿不会改变已启动的流程。

拖动节点标题调整位置；点击输出端口，再点击目标节点输入端口连线。端口支持键盘 Enter/空格，节点支持方向键移动。选中节点或连线后按 Delete 删除。Ctrl/Cmd+Z 撤销，Shift+Ctrl/Cmd+Z 重做。画布空白处拖动平移，底部控制缩放与适应画布。

从运行记录选择实例后，画布显示该实例固定的发布版本，不能编辑；“编辑草稿”返回当前草稿。节点状态和时间线来自实际执行记录，点击一次节点执行可以检查输入、输出、会话、上下文及错误。

## 节点与数据

| 节点 | 行为 |
| --- | --- |
| 入口、结束 | 接收初始变量与事件，结束该条执行路径 |
| Agent | 使用现有专家、模型路由、工具权限和会话锁执行指令 |
| 脚本任务 | 在明确绑定的执行环境创建持久 Job，按真实回执等待完成 |
| 条件 | 对显式输入做声明式比较，经 true/false 端口选择后续路径 |
| 注册事件、等待事件 | 为一次节点执行注册回调，保存提前到达的数据，单次消费 |
| 定时等待 | 到达指定时间后继续，不占用模型轮次 |
| 并行分支、汇合 | 在配对区域内并行，按分支键显式合并结果，避免最后写入覆盖 |

节点输入和变量赋值使用 `{ "value": 123 }` 或 `{ "path": "$.vars.threshold" }`。可引用 `$.vars`、本分支最新已完成节点的 `$.outputs.<节点ID>`、`$.event`，支持对象键和数组下标。不执行表达式或模板代码。

Agent 和脚本输出包含 `text`，JSON 模式另有 `result`。例如条件读取 `$.outputs.analyze.result.continue`。大日志和完整会话通过 Job/会话证据引用查看，运行状态只保留有界摘要。

脚本的 argv 是固定参数列表，解析后的输入通过环境变量 `OCTOPUS_WORKFLOW_INPUT` 传入 JSON。脚本节点或流程必须绑定已有的、属于当前用户的执行环境；未指定工作目录时使用该环境的工作目录。

## 节点前后的会话与上下文

执行前可使用当前会话或新建独立会话，并选择继承历史、最近若干轮或空历史。额外注入内容可以是文本或绑定值，以用户数据优先级传给模型。

执行后独立选择“会话”和“上下文配置”各自保留或恢复。例如，新建会话分析，执行后返回原会话，同时保留“最近 8 轮”的配置。后续节点会在原会话上重新投影最近 8 轮，不会把子会话全文导入原会话。历史投影保留受保护系统消息和工具调用/结果完整性，完整归档不被删除。

新会话仍属于原用户，使用相应专家及已有服务器权限；切换会话不会扩大权限。并行分支默认在汇合后恢复分叉前会话/配置，也可选择一个分支的上下文。

## 定时与事件

定时配置使用五字段 cron 和 IANA 时区，空时区在保存时采用服务器默认时区。重启跳过错过的触发点，不回放积压日程。默认前次未完成时跳过本次；可显式选择并行，但仍受队列和运行预算限制。

事件有两种用途：

1. 唤醒已有运行。注册事件节点产生作用域受限的 URL；脚本的 `callback_node` 指向该节点后，通过私有环境变量获得 `OCTOPUS_WAKEUP_URL`、`OCTOPUS_WAKEUP_TOKEN`。POST 内容是 `{ "event_type": "evaluation.done", "data": {...} }`，请求头为 `X-Octop-Wakeup-Token`。事件类型必须与注册配置一致。等待节点的 `event_node` 指向同一注册节点。
2. 启动新运行。流程启用 `event_start` 并发布后，在设置获取事件入口。向 URL POST `{ "event_id": "稳定的事件ID", "data": {...} }`，请求头为 `X-Octop-Graph-Token`。同一事件 ID 和相同数据重复投递返回同一次运行，不能用同一 ID 投递不同数据。撤销入口会轮换凭据。

事件数据最多 8192 UTF-8 字节，只作为不可信数据，不能改变专家、执行环境或流程权限。回调凭据不出现在普通节点检查中。注册事件每轮产生独立入口，已消费的一次信号不能供下次循环再次消费。

脚本任务完成与事件到达是独立条件。脚本节点依据持久 Job 回执完成，等待事件节点消费回调；仅收到回调不会伪造脚本完成。

## 暂停、恢复与预算

默认每次运行最多 100 步、24 小时、4 个并发计算任务；设置可调整到允许范围。等待事件、时间和已受理 Job 不占模型轮次。全局计算受理也限制为 4，排队按用户轮转。

达到步骤或时间上限会暂停后续节点，已运行的命令保留。可以补充预算并恢复。普通暂停/取消也保留已接受的 Job；“取消运行中的任务”单独请求取消各 Job，并展示各自实际回执。

重启恢复排队和等待状态。模型运行中断或已受理命令缺少明确证据时，显示 unknown。先用“核对回执”观察原操作；“重试节点”是明确授权创建一次新执行，可能再次产生副作用。系统不会自动重跑不确定的实验。

## Agent 自主配置

Agent 可使用 `workflow_graph` 或对应的具名工具创建、校验、保存、发布、启动和观察流程。保存使用预期 revision；新流程 revision 为 0。发布和启动是独立操作。运行与节点检查、暂停/恢复/取消、核对回执、显式重试和事件入口管理使用同一服务。

当前登录用户、专家、会话和执行来源来自可信运行配置，不能用工具参数冒充其他用户。Ask/Plan 模式只允许观察和校验，不能发布、启动或获取事件凭据。

可以给 Agent 这样的任务：

> 根据当前研究先验和服务器规矩，创建“评估 → 分析改进 → 判断是否继续”的流程。使用当前已授权执行环境，保留每轮实验回执。分析返回结构化继续条件，配置明确的步骤/时间预算。先校验并保存，再按我的指令发布和启动。

## 示例与维护

`docs/examples/workflow-graphs/` 包含每日复盘、评估迭代和事件反馈定义。导入后将 `your_expert` 与 `your_execution_context` 替换为自己的已有资源，并调整脚本路径。示例不会自动发布或启动。编辑器内也提供空白、每日、迭代和事件模板。

实现位于 `src/octop/infra/workflow_graphs/`，SQL 仅在 `infra/db/repos/workflow_graphs.py`。迁移 040 提供 SQLite/PostgreSQL 对。API 在 `/api/workflow-graphs`，可在 `/api/docs` 查看类型化接口。测试运行 `uv run pytest tests/unit/workflow_graphs tests/integration/test_workflow_graphs.py -q`；前端测试位于 `dashboard/src/pages/WorkflowGraphs/`。
