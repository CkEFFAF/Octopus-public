# 多用户内测准备：账号管理权限加固

基准：远端 `main`，`55e0dbf45e1837614ad94b111692a82a29d29957`，于 2026-10-24 核实。

## 本轮行为

本轮处理用户、角色和邀请码的委派管理边界。管理员可以管理所有账号；持有 `users` 权限的普通账号只能修改非管理员账号，而且目标账号的权限必须全部在操作者已有权限内。该检查覆盖账号编辑、改密、解锁、删除、头像和批量操作，避免通过重置高权限账号密码取得该账号的能力。

角色模板的编辑、删除和头像操作使用相同边界。应用角色时，无论请求是否显式提供 `permissions`，最终授予的权限都先经过验证，再写入账号。单个账号更新与批量操作都禁止停用自己。

管理员可以查看和撤销全部邀请码。普通用户管理员只能查看和撤销自己创建、且对应角色仍在当前权限范围内的邀请码；其他人的邀请码和管理员邀请码不会出现在响应里。角色被删除后，创建者仍可撤销已经无法使用的邀请码。服务层要求显式传入操作者，不能省略身份检查。

普通用户管理员仍可创建、编辑、重置密码和删除权限范围内的普通账号。未指定角色的邀请码继续创建无模块管理权限的普通用户。

邀请码的创建、兑换和撤销审计只记录 `invite:<ID>`。HTTP 审计日志和 CLI 审计输出还会遮蔽历史记录中的原始兑换码，避免从另一条读取路径获得邀请码。

## 验收

| 场景 | 预期 |
| --- | --- |
| 普通用户管理员重置管理员或权限更高账号的密码 | 返回 403，目标账号不变 |
| 通过编辑、删除、解锁或头像接口控制高权限账号 | 返回 403，写入前拒绝 |
| 批量请求混合包含管理员、高权限账号和可管理账号 | 前两者逐项失败，可管理账号成功 |
| 切换到含有操作者未持有权限的角色，省略 permissions | 返回 403，角色和其他字段均不变 |
| 普通用户管理员读取邀请码列表 | 不返回其他人或越权角色的邀请码与兑换码 |
| 管理员或普通用户管理员停用自己 | 返回 403，当前账号仍可访问 |
| 管理员正常管理其他账号，受委派账号管理权限内的普通账号 | 保持可用 |

## 后续内测前仍需完成

本轮修复没有把系统判定为已经可以对外开放。当前 `POST /api/auth/logout` 仅写入审计日志；修改或重置密码也不撤销已签发的普通 JWT。应继续实现服务端可撤销会话，并验证退出、改密、停用后重新启用和已建立 WebSocket 的会话行为。

数据隔离仍需覆盖真实的双账号使用流程：会话与附件、知识库内容与索引、连接器凭据、模型密钥、设备与远控、定时任务和导出。已有账号级所有权实现和自动化测试是基础，不能代替真实双账号验收。

还需在内测部署上验证资源配额和并发运行，确认一个账号耗尽额度或出现失败时不会阻塞其他账号；随后再创建有限额的测试角色并发出单次邀请。角色模板在兑换时读取，因此调整角色权限前要检查仍有效的邀请码。

本轮不创建真实测试用户，不发出邀请码，不变更线上访问权限。
