# Octopus 快速部署

本版本沿用 Octop 的管理服务和账号体系。一个常开管理端保存账号、智能体、
群聊、看板和设备操作记录；其他电脑只运行设备客户端，不创建第二套账号库。

## Windows 管理端

使用本仓库构建的 Windows 便携包，完整解压到固定目录。双击 `open.bat`，
首次按页面向导设置账号和模型。需要排查启动问题时运行 `start.bat` 查看日志。
数据默认保存在包内 `data`；可以指定独立数据目录：

```powershell
.\start.bat --home 'D:\OctopusData\manager' --host 127.0.0.1 --port 8188
```

本机打开 `http://127.0.0.1:8188`。远程设备和手机使用管理端的真实地址；
`0.0.0.0` 是监听配置，不是浏览器访问地址。其他机器不能用 `127.0.0.1`
访问管理端。常态远程使用可信 HTTPS / 私有网络，按实际地址配置防火墙。
远程 HTTP 联调必须在客户端明确确认；该例外不提供传输加密。

## Windows / Linux 设备第一次接入

1. 在管理端用现有 Octop 账号登录，进入「设备 → 配对设备」，生成配对码。
2. Windows 完整解压 Windows 便携包，双击 `start-device.bat`。
   Linux 解压匹配架构的无界面设备包后运行 `./start-device.sh`。
3. 向导中填写管理端地址、设备名称，选择权限方案和共享目录，核对后确认。
4. 在隐藏输入中粘贴配对码，也可使用管理端生成的设备接入密钥。
   成功后客户端立即连接，管理端自动显示设备和在线状态。

不用创建另一个 Octop 账号，不用输入 Windows / Linux 系统登录密码，不用
事先创建密钥文件。重新启动只运行同一个入口，复用私有 `device-state`
内保存的独立身份和权限。已登记设备单独撤销；撤销接入密钥不会撤销既有设备。

| 权限方案 | 文件 | 桌面 | 命令 |
| --- | --- | --- | --- |
| 文件和终端 | 共享目录读写 | 关闭 | 每次确认后执行 |
| 桌面和文件（Windows） | 共享目录读写 | 查看与键鼠控制 | 关闭 |
| 仅查看文件 | 共享目录只读 | 关闭 | 关闭 |
| 自定义 | 首次明确选择 | Windows 可选择 | 首次明确选择 |

共享目录限制文件传输范围。命令以客户端当前系统用户身份执行，具有该用户的
操作系统权限；它不是文件系统沙箱。Linux 无需桌面、浏览器或完整管理服务。
Windows 桌面控制要求用户已登录桌面及相应采集依赖。

向导不安装自启动。当前前台客户端终端需要保持运行，关闭浏览器不影响连接。
如以后需要自启动，在客户端停止后明确执行 `setup-device.bat autostart install`
或 `./setup-device.sh autostart install`；Windows 是登录后任务，Linux 是
systemd 用户服务。Linux 服务与开机条件见 [设备包说明](../../desktop/portable/linux-device/README.md)。

已有显式参数接入和 `--key-file` 保持兼容。新增另一个独立管理端时先停客户端，
再运行 `setup-device.bat` / `./setup-device.sh`；各管理端分别授权、分别持有
自己的账号库和项目，不能靠同名账号自动同步。

## 手机与日常操作

Android / iOS 浏览器访问同一管理端地址，用原账号或允许浏览器登录的密钥登录。
在设备列表选择在线设备，再进入文件、终端或桌面工作区。管理端和目标设备
客户端都需要运行。手机离开当前网络后，必须仍能到达管理端的私有网络或 HTTPS
地址；浏览器适配不等于已经完成跨网络连通配置。

## 数据与源码分开

`data`、`device-state`、数据库、接入密钥、迁移口令和 `.octopmove` 备份属于
部署数据，不提交 Git，也不放进分发包。需要迁移管理端时先停原实例，通过
`move-manager.bat` 加密导出并恢复到新目录，核对原账号与数据后再迁址客户端。
不能同时运行两份可写的同一管理实例。

源码部署与构建见 [开发说明](run-and-build.md)。
