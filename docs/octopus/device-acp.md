# 专家绑定设备与 ACP

当前合同为 [0015 revision 3](../specs/0015-device-execution-and-context-inspection.md)。
专家的 `device_binding` 保存默认目标设备和可选原生工作目录；旧 restricted 绑定
仍可保存共享目录 ID。实际优先级为会话明确选择 → 专家默认 → 账户默认。
会话选择不会修改专家的长期默认设置；每次 Run 冻结 ExecutionContext，已有终端、
浏览器和 ACP 会话保留原目标，不能被其他会话的选择悄悄改绑。

owner 模式按设备运行的 OS 用户权限访问原生绝对路径和相对路径，工作目录只是
起始位置，不是共享边界。正常文件、命令、桌面操作不逐次询问。持久策略可以禁用
能力，变更具有 desired/applied revision 回执。restricted/旧客户端继续沿用共享目录
和确认流程；不能把它们显示为已支持 owner 协议。

开启 ACP 工具后，OpenCode Go、Codex 等 runner 的**启用状态和启动命令**仍由
Octop 账号的 ACP 设置决定；实际进程在绑定设备上运行，并读取该设备当前操作系统
用户自己的安装、登录状态和配置。工位管理端不向设备传递本机环境变量或 API Key。
选定设备离线、策略未应用、缺少 `acp_run` 或 runner 未安装时，调用失败，不回退到
管理端的同名程序。管理端本机是单独的管理员显式选项，空设备 ID 不表示本机。

## 为现有设备开启

`acp_run` 是独立能力。更新管理端与设备运行器时保留原 device_id、凭据、控制中心
身份和资料，通过设备策略回执确认新能力，不能为普通升级重新配对重复登记。
专家编辑页保存默认设备/目录，个性化 → ACP 启用对应 runner；设备上仍须安装并
登录该 CLI。能力目录发现命令存在，不等于已验证 CLI 登录或 MCP 服务可连接。

ACP 以目标设备当前 OS 用户权限运行，不是文件沙箱，可能读写共享目录以外的文件
或执行命令。owner 模式不额外添加设备级逐次确认；外部 CLI 自身的交互仍按其实际
协议处理。只在你信任的设备和管理端上开启。断开设备连接或撤销授权时，客户端结束
该连接启动的 ACP 进程。ACP 输入输出不写入设备操作日志；日志只留启动/关闭元数据。

当前连接仍采用已配置的设备传输。跨网络运行应使用 HTTPS 或可信私有网络；HTTP
不会因 ACP 功能自动加密。手机可从管理页发起聊天，ACP 程序仍在绑定的 Windows /
Linux 设备运行。

## 工作台与旧桌面目标

聊天工作台的文件、Git、终端、浏览器、桌面面板使用显式冻结的 ExecutionContext。
切换设备影响新任务和新面板；已打开面板继续标明原设备。owner 桌面查看/输入无须
被控端逐次确认；界面开启查看/输入只是主动启动交互，不是共享审批。

旧独立桌面目标入口保留兼容行为，不修改专家默认绑定，也不热迁移已有会话内存。
新架构的实际设备验收和发布状态见 [架构进度](execution-architecture-progress.md)。
