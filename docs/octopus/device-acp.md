# 专家绑定设备与 ACP

专家的 `device_binding` 保存目标设备 ID 和一个可读写共享目录 ID。专家编辑页可以
选择、取消绑定；保存时管理端核对设备归属及目录权限。绑定后，专家使用设备工具
也只能操作该设备，聊天里的临时设备选择不能改写绑定。

开启 ACP 工具后，OpenCode Go、Codex 等 runner 的**启用状态和启动命令**仍由
Octop 账号的 ACP 设置决定；实际进程在绑定设备上运行，并读取该设备当前操作系统
用户自己的安装、登录状态和配置。工位管理端不向设备传递本机环境变量或 API Key。
绑定设备离线、未授予 `acp_run`、共享目录失效或 runner 未安装时，调用失败；不会
回退到工位上的同名程序。未绑定专家仍按原逻辑在管理端运行 ACP。

## 为现有设备开启

`acp_run` 是独立能力。旧设备的权限不能由管理页单方面扩大。先更新管理端与目标
设备客户端；在目标设备本机重新配对，向导里单独同意 ACP，并选可读写共享目录。
也可用 `device connect` / `device add-controller` 的 `--allow-acp` 参数。旧设备条目
验收后可撤销；如复用设备名称，以设备 ID 区分新旧条目。专家编辑页选新设备及
共享目录，再在个性化 → ACP 中启用目标 runner。设备必须已安装并登录对应 CLI。

ACP 以目标设备当前 OS 用户权限运行，不是文件沙箱，可能读写共享目录以外的文件
或执行命令。ACP 会话权限提示仍由用户选择；`acp_run` 不提供设备命令操作的逐次
确认。只在你信任的设备和管理端上开启。断开设备连接或撤销授权时，客户端结束
该连接启动的 ACP 进程。ACP 输入输出不写入设备操作日志；日志只留启动/关闭元数据。

当前连接仍采用已配置的设备传输。跨网络运行应使用 HTTPS 或可信私有网络；HTTP
不会因 ACP 功能自动加密。手机可从管理页发起聊天，ACP 程序仍在绑定的 Windows /
Linux 设备运行。
