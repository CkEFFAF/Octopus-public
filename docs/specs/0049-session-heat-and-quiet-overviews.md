# 0049 会话热度与安静时段概览

**Status**: In Progress
**Date**: 2026-11-08

## Summary

让有任务、常用和近期频繁交流的会话更容易找到。热度同时有文字和颜色提示，置顶仍然优先。自动概览避开密集交流，合并变化，在用户较少活动的时段静默补齐，手动更新保持即时。

## Context

现有列表只按置顶与最后活动时间排列。工具和后台事件会更新活动时间，不能将它们当作用户交互次数。自动概览在来源变化后五秒入队，持续交流会反复产生更新。

历史消息有投影和独立归档两种来源，单独统计 thread_messages 会遗漏新版归档。需要统一的无正文活动记录，使用消息或命令的稳定标识去重；历史补齐只读取角色、标识与时间等元数据。

## Requirements

1. AC01，热度使用近期真实用户输入、任务频次与未完成后台任务，分数为 0 至 100。工具续调、恢复与同一命令重试不增加用户次数。
2. AC02，记录和查询按用户、专家、会话隔离。统计不保存正文、附件字节或凭据。历史没有可靠信号时保留未知，不能伪造交互次数。
3. AC03，置顶会话在前，其余优先显示热度较高的会话，再按最近活动及稳定会话 ID 排序。排序在截取列表页之前完成；旧的活跃任务不会被最近列表分页漏掉。
4. AC04，常规与紧凑侧栏均显示可辨识的任务状态、热度文字及颜色。说明里能查看评分依据，不仅依赖颜色。长标题、窄屏、深色和键盘焦点可用。
5. AC05，连续用户交流和正在进行的回答推迟自动概览。热度越高，短期自动更新间隔越长；只处理已有脏数据，不建立循环的无变化模型调用。
6. AC06，有足够历史活动样本时，选择较少活动的小时窗口；不足时使用实际空闲时间。推迟有上限，避免会话长期遗忘；手动刷新和明确的整理请求不受自动节流影响。
7. AC07，复用原有持久化队列的去重、租约、重试、取消和来源版本检查。自动推迟不消耗失败重试次数，不破坏正在运行的任务。
8. AC08，概览显示计划更新时间或推迟原因。恢复、手动刷新、账号切换和旧客户端保持兼容；缓存快照继续按用户消息固定。

## Decision

在现有 Python、SQLite/PostgreSQL、React 和概览队列内增量实现。新增无正文活动记录，合并已有任务信号；不调用模型识别活跃程度，不增加外部分析服务。迁移折入尚未发布的 039，与缓存可用性一同演练和备份。

自动概览以最新用户输入时间、上次成功时间和账号小时分布确定 not_before。手动任务保持原入口。沿用每会话一个 auto 去重键，新的脏事件不能把既定安静时段改回五秒后。

## Value sourcing

| 值 | 来源 |
| --- | --- |
| 用户交互 | 已受理输入的消息或命令 ID、所属账号/专家/会话与受理时间，重试唯一键去重 |
| 历史交互 | 原投影及独立归档中的用户角色、稳定消息 ID 和时间；不读取正文用于评分 |
| 任务活跃度 | 账号可见 work_items 与已确认仍活跃的后台 Job，使用现有过期判断 |
| 工作频次 | 最近七天任务创建次数和用户输入频次，工具步骤不单独计数 |
| 最近活动 | 最新真实用户输入；无用户样本的旧会话只使用原 last_active 作为宽泛活动信号 |
| 安静窗口 | 最近四周账号输入的 UTC 小时分布；计算绝对时间后由现有本地时间展示 |
| 概览新鲜度 | thread_metadata.generated_at、dirty、来源修订与已排队任务的 not_before |

## Feature design

分数按有上限的分量相加：未完成任务最高 40 分，最近 24 小时交互最高 30 分，七天任务与用户交互频次最高 15 分，随时间衰减的近期活动最高 15 分。任务进行中优先标明，等待用户处理单独提示；其他会话依据分数显示常用、活跃或安静。相同分数沿用原先时间顺序。

自动更新基准间隔为普通会话 5 分钟、活跃会话 15 分钟、较高热度 30 分钟。最新输入后至少空闲 5 分钟；仍有活动回答时再次延后。有至少 30 个输入且跨三个日期的历史时，选未来较少活动的小时，额外等待最多 6 小时。没有变化不排队，手动刷新跳过这套自动规则。自动等待状态给出实际计划时间和原因。

批量读取同一账号专家的候选会话与活动统计，在排序后分页，再一次性加载展示摘要。不为每条侧栏记录分别请求。交互记录保留最近 90 天，时段统计只读取最近四周。

## Options considered

只按现有 last_active 打分最简单，但会让工具调用密集的会话冒充用户常用会话。直接依赖旧消息投影会漏掉新版归档。选用统一活动记录与历史元数据补齐，便于去重、解释和限制保留期限。

## Build plan

- [x] 迁移、活动记录、历史信号补齐与批量热度统计，AC01 至 AC03。
- [x] 侧栏排序、状态文字、颜色与依据说明，AC03、AC04。
- [x] 概览自动节流、安静时段与计划状态，AC05 至 AC08。
- [ ] 去重、跨账号、分页、手动优先及真实页面验收，AC01 至 AC08。

## Consequences

热度是解释清楚的使用信号，不是任务重要性的推断。样本不足时不声称知道用户作息。安静时段会让自动概览更晚更新，界面显示计划时间，用户仍可立即手动整理。

## Rationale

沿用现有队列可保留取消、幂等和断点恢复边界。记录用户输入元数据避免把工具数量当成用户偏好，也让两种历史格式共用同一评分口径。
