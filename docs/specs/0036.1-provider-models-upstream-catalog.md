## 1. Goal and boundaries

**用户/调用方**：管理台「设置 → 模型」账号管理员（尤其 OpenCode Go Compatible 等 openai-compatible 提供商）。  
**问题**：0036 S0 已提供卡片「更新模型」与 `refresh-models`，但 `probe.fetch_openai_compatible_models` 对 OpenCode Go 用 **bundled preset 模型 id 集合做远端∩过滤**，远端新 id（如 `omen-alpha`、`gemini-4-argon-contributor`、`minimax-m3.1-flash-free`）被静默丢弃；元数据/价格仍依赖过期的 `provider_template.json`。  
**结果**：有 api_key 时，卡片「更新模型」写入远端 **全部可见** model id（`source=remote`）；bundled preset **只增强、不当过滤器**；可选从 **models.dev** 补齐空字段（价/上下文/能力）；models.dev 失败 **不阻塞**「至少出现模型 id」。顶栏 Refresh 仍只重读 DB。

### In scope
- 去掉 Go（及同类）远端列举上的 preset 白名单交集
- refresh 合并后 best-effort 上游目录 enrich（选定 **models.dev**）
- 单测：Go 新 id 不被丢；enrich 失败仍落库 id
- 与 0036/#46 边界与排期写清

### Non-goals
- **不重做** 0036 S0（卡片按钮、`POST .../refresh-models`、永不静默删 user、顶栏 DB-only）
- **不**在本规格 S0 实现 Anthropic / Gemini **官方** List Models API（见分期 / OQ；与 0036 DEC-0036-5 一致）
- 不要求「上游当天实时」；要求后续点「更新模型」能跟上
- 不部署云端；不升级整包 harness 发布流水线仅为更新模板
- 不做「清理远端已下线模型」的自动删除（仍须另开规格 + 二次确认）
- 不强制 UI 展示价格徽章（字段可先落库/enrich；展示可 S1）

### Constraints / deps
- 依赖 0036 S0 代码：`refresh.py`、`merge_models_with_source`、`ProviderCard`「更新模型」、`source` 字段
- 排期（二选一，Coder 按合入状态选）：
  1. **#46 已合入 main** → 从新 main tip 开 `feature/0036.1-provider-models-upstream`
  2. **#46 未合入** → 基于 `feature/0036-provider-models-refresh` @ `b400b469`（或更新 tip）续做同名分支 / 叠分支；合入顺序 #46 → 本 PR rebase
- 相关路径：`probe.py`、`refresh.py`、`catalog.py`（只读理解 Go 身份）、`presets.py`、可选新建 `models_dev.py` / `upstream_catalog.py`

## 4. Requirements and acceptance

### REQ-001 — 远端全量 id（解除 preset 白名单）
- Source: 用户「有 key 应探测支持的模型；不被 preset 卡死」
- Requirement: 对 openai-compatible + api_key 的 refresh（含 OpenCode Go Compatible），`fetch_openai_compatible_models` 返回远端 list 中全部合法 id（去重、排序可保留）；**禁止** `mid not in go_model_ids` 一类过滤。Go list URL 改写可保留。
- AC-001: Given OpenCode Go Compatible 已保存且有 key，When mock/real 远端 `data` 含 preset 没有的 `omen-alpha`（及/或 `gemini-4-argon-contributor`、`minimax-m3.1-flash-free`），Then refresh 后 DB `models_json` 含这些 id，且 `source=="remote"`，`enabled==false`（新建时）。
- AC-002: Given 用户已有手工模型 `my-custom-model`，When refresh，Then 该行仍在且不被删除（回归 0036 AC-008）。
- Verification: `tests/unit/` 针对 probe 过滤移除 + refresh 集成；禁止再依赖「远端∩preset」断言。

### REQ-002 — models.dev enrich（失败不阻塞）
- Requirement: refresh 在得到 merged 列表后，best-effort 拉取 models.dev，按 provider 映射 + model id 匹配，填充空元数据；进程内缓存建议 TTL **6h**（可配置常量）；超时建议 ≤ 10s，失败记日志。
- 字段映射（S0 最小集）：

| models.dev | Octopus model 字段 |
| --- | --- |
| `name` | `name`（仅当空或等于 id） |
| `limit.context` | `context_window`（空时） |
| `limit.output` | `max_output_tokens`（空时） |
| `modalities.input` | `input`（空时） |
| `reasoning` | `reasoning`（空时） |
| `cost` | S0 可选：若模型 dict 已有/易加 `cost` 则写入；否则记 OQ-0036.1-2，不阻塞 |

- AC-003: Given models.dev 可达且含该 id，When refresh，Then 新建 remote 行在空字段上获得上下文/名称等 enrich；`ok==true`。
- AC-004: Given models.dev 403/超时/JSON 坏，When refresh，Then 远端新 id **仍写入**，`ok==true`（除非远端 list 本身失败且无 preset 可降级——仍循 0036 规则）。
- Verification: 单测 mock httpx；不强制打真网。

### REQ-003 — 产品语义与 0036 对齐
- AC-005: 顶栏 Refresh 仍只重读 DB，不触发 models.dev / 远端 list。
- AC-006: 卡片「更新模型」才探测；成功 toast 可沿用 0036 文案（added/source）；无需为 S0 强制改 FE（若加 `upstream_enriched` 计数则可选）。
- AC-007: 非 Go 的普通 openai-compatible：行为与 0036 一致，且同样不得引入新的 preset 白名单过滤。

### REQ-004 — Anthropic 远端（本规格定位）
- Requirement: S0 **不**扩展 `remote_list_supported` 至 `anthropic`；OpenCode Go Anthropic 仍 preset-only（或 0036 已有行为）。S1 再评估 Go Anthropic 是否有可复用 list 端点 / 官方 API。
- AC-008: 规格与测试不声称 Anthropic 已远端全量；代码注释或 OQ 指向 S1。

### REQ-005 — 验收与回归
- AC-009: 新增/扩展单测覆盖：Go 新 id 不被丢；enrich 失败不阻塞；0036 既有 refresh 单测全绿。
- AC-010: Playwright **可选**：若改 FE 文案则补截图；纯后端可只跑单测 + 手工点一张 Go 卡（内测）。

### 实现伪流程（refresh，S0）
```
remote = fetch_openai_compatible_models(...)  # Go: 全量 id，无交集过滤
merged, stats = merge_models_with_source(current, remote, preset_models)
try:
    merged, n = enrich_from_models_dev(merged, provider_row)
    stats["upstream_enriched"] = n
except Exception:
    log; stats["upstream_enriched"] = 0
persist merged  # 与 0036 相同
```

### models.dev 约定（Coder）

- Provider 映射（S0 硬编码表即可）：

| Octopus preset id / 显示名 | models.dev key |
