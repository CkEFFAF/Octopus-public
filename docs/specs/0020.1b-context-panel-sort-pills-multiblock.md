## Goal

在已上线 0020.1a 上立刻改两处，让 Context dock **看起来像 dsh-context 一页多个小块**，而不是「一个大功能区 + 下拉选」：

1. **排序**：去掉「时间 ∨」`Select` 下拉。改成 **「时间 | Token」并排 pill / Segmented**，点一下即切；升/降序按钮可保留。
2. **布局**：Request Browser 等大区拆成**多个独立小卡片**（各卡自有标题 + 紧凑 chrome + 限高区内滚）；列表**可见列出**，禁止再用下拉「选一条才看见」。
3. **按标签过滤**：标签/种类以可点 **pill/chip** 列出（对齐 dsh `.lc-chip`），与「时间|Token」同区或紧邻；**禁止**藏进下拉；无标签时空态清楚。
4. **回执主视图可读（人+机器）**：主卡片优先 **动作名、时间、耗时、命令摘要、退出码+成功/失败、工作目录**；有则展示 stdout/stderr **短摘要**（截断 + 可展开全文）。`runId` / `deviceId` / `operation_id` 等进「技术字段」折叠（默认可复制、不占主视线）。payload 没收的字段：**禁止伪造**，标缺口并走最小补字段路径（见 §2.6 / OQ-CMD-01）。

## Non-goals

- 不新造平行 Context 面板 / 不改 dock tab 注册。
- 不改 work_mode / 证据校验 / receipt **记账与校验**语义（允许改 `RunReceiptBrowser` **展示层级**）。
- 不改 0020.1a 已落地的：`.panel` 滚动链、`.dockTabBody { display:flex }`、比较器缺 token 沉底、默认时间降序。
- 不实现 File Activity（仍无 UI 则跳过）。
- 不做 Preferences 持久化。
- 不借机重构 ChatDockPanel / Ring meter。

## 1. 排序控件契约（替换 0020.1 §2.1）

### 1.1 形态（强制）

```
[标题] .............. [ 时间 | Token ]  [↑↓]  [刷新?]
```

- **字段**：`antd` `Segmented`（或等价 pill 组），**不是** `Select`。
- **方向**：现有升降 `Button` 可留；`aria-label` 含当前方向。
- **禁止**：任何「排序字段」用途的 `Select` / Dropdown / Cascader。
- 放置：每个列表卡 `.cardHead` 右侧（Browser + Events；File 若有则同）。

### 1.2 语义（沿用 0020.1a，不改）

| 控件值 | Request Browser | Events |
| --- | --- | --- |
| 时间 | `seq`（无则 `created_at`） | `seq`（无则 `ts`） |
| Token | `actual_usage.input_tokens` ?? `estimated_input_tokens` | `payload.input_tokens`（无则缺字段沉底） |

默认：两区皆 **时间 + 降序**。缺 token **无论升降皆沉底**。会话内 `useState`，不写 localStorage。

### 1.3 验收

| ID | 要求 | AC |
| --- | --- | --- |
| REQ-SORT-B01 | 排序字段为并排 pill，无下拉 | AC-SB01：手测 / DevTools——Browser 与 Events 标题行 **无** `.ant-select` 用于 sortKey；存在 `Segmented`（或 pill）含「时间」「Token」两选项；点击即切，无展开面板 |
| REQ-SORT-B02 | 升降按钮仍可用 | AC-SB02：点方向按钮立即重排；默认时间降序与 0020.1a 一致 |
| REQ-SORT-B03 | 比较器语义不变 | AC-SB03：Token 降序最大 input 置顶；缺 token 沉底；Trend 高亮 `scrollIntoView` 仍有效 |

## 2. 多小块布局契约

### 2.1 目标 IA（上→下）

```
.panel (外滚)
├─ card: Header / 会话摘要（可极简）
├─ card: Stats（格）          ┐ 宽屏可两列并置
├─ card: Current occupancy    ┘
├─ card: Trend（柱 + grain/metric Segmented）
├─ card: Request 列表（排序 pills + 可见行/chip + 区内滚）
├─ card: Request 详情（仅选中项：status/stats/composition/components；限高内滚）
├─ card: Events（排序 pills + filter + 列表区内滚）
└─ card: Receipts（可选，限高）
```

**铁律**

- 每卡：自有标题（`.cardHead`）、`lc-card` 级 padding（已有 8–10px 可保留）、`margin` 间距 ≈7–8px、圆角 ≈10px。
- 列表卡：`.sectionBody` + 既有 `max-height`（0020.1a）；**禁止** list section `flex:1` 撑满。
- **禁止**单一 section 同时承载：趋势柱 + 请求 Select + 详情大块（今日 Browser 形态）。拆成「列表卡」+「详情卡」。
- 同屏至少能看见 **≥3** 个分区标题（不靠滚完才发现只有一块）。

### 2.2 Request 列表（替换「非得选」）

今日问题（`67cf3e4`）：`ContextRequestBrowser` 在同一 `section` 内叠：trend 柱 + **`Select` 选 `#seq`** + stats + composition… 用户必须下拉才「看到」请求。

目标：

1. **列表卡**：排序 pills +（可选保留迷你 trend 或把它留在独立 Trend 卡）+ **可见 request 行列表**（每行：`#seq` · model · tokens · status 摘要）；点击行 = `setPicked`；高亮选中行；区内滚。
2. **详情卡**：仅渲染当前选中 request 的 stats / composition / components / transformation；无选中时 Empty「点上方列表查看」。
3. **删除**列表选请求的 `Select`（`requestHeading` 那个）。若实现上需要键盘可达，可用 listbox 角色，**不要** Ant Select。

> 注：面板顶部独立 **Trend** 卡已存在于 `ChatDockContext`；Browser 内再嵌一整条 trend 易加重「一大块」。本补丁优先：**去掉 Browser 内重复大 trend，或缩成列表卡顶一行迷你 sparkline（高度 ≤48px）**。二选一由 Coder 取更小 diff；验收以「多小块 + 列表可见」为准。

### 2.3 密度

沿用 0020.1a §1.3；本补丁不强制再砍 padding。宽屏两列仅摘要卡。

### 2.4 验收

| ID | 要求 | AC |
| --- | --- | --- |
| REQ-LAY-B01 | 多独立小卡片 | AC-LB01：DOM 上 Request 列表与 Request 详情为**两个** `section`（或等价 `.card`）；截图同屏可见 ≥3 个分区标题 |
| REQ-LAY-B02 | 请求可见列出 | AC-LB02：≥2 条 request 时，不打开任何下拉即可看见至少 2 行/chip；**无** `#seq · model` 用途的 `Select` |
| REQ-LAY-B03 | 区内滚保留 | AC-LB03：列表超 `max-height` 时仅该卡内滚；其它卡标题仍可经 `.panel` 外滚到达 |

### 2.5 按标签过滤（pill，与排序同区）

**放置（强制）**

```
[标题] .... [ 时间 | Token ] [↑↓] 
            [ 全部 | Inject | Compact | … ]   ← 标签 pill 行（可换行）
```

- 标签 pill 与排序 pills **同卡标题区或紧邻下一行**，一眼可见；**禁止**再放进 `Select` / Dropdown。
- 形态对齐 dsh `.lc-chip` / 现有 Trend `Segmented`：点一下即滤；选中态清晰（`.lc-chip-on` 或 Segmented value）。
- 可选：pill 上显示该标签条数（如 `Compact 3`）。

**标签数据源（本仓映射，不造新后端）**

| 列表卡 | 标签来源 | 说明 |
| --- | --- | --- |
| Events | `mapTrajectoryKind` → `MAPPED_KIND_FILTERS`（all/inject/compact/prune/…） | 今日已是 Segmented；本补丁须保证为**可见 pill 条**（可继续用 Segmented），并与排序同区 |
| Request 列表 | 当前页 requests 出现过的 `component.kind` / composition key | 无 kind 多样性时可不渲染 pill 行，改空态 |
| Receipts | 可读维度：`status`（ok/failed）+ `kind`（job/workflow/…）；**不用** raw run ULID 当 pill 文案 | 替换今日 `Select options={run_id}` |

**空态**

- 当前数据集推导后 **0 个可用标签**（除「全部」外）：显示一行次要文案「暂无标签可筛选」，**不**出现空下拉、不占假 pill。
- 选中某标签后 0 条命中：列表 Empty「无匹配项」+ 一键回到「全部」。

| ID | 要求 | AC |
| --- | --- | --- |
| REQ-TAG-B01 | 标签以可点 pill 列出 | AC-TAG01：Events 卡可见 ≥1 行 kind pill（含「全部」）；DevTools 确认过滤控件 **不是** `.ant-select` |
| REQ-TAG-B02 | 与排序同区 | AC-TAG02：同一列表卡内，排序「时间\|Token」与标签 pill 同属标题工具带（同 `.cardHead` 或紧邻），无需另开菜单 |
| REQ-TAG-B03 | 无标签空态清楚 | AC-TAG03：构造/找一个无多样 kind 的会话——不出现空白 Select；有「暂无标签」类文案或仅保留「全部」 |
| REQ-TAG-B04 | Receipts 不以 ULID Select 过滤 | AC-TAG04：`RunReceiptBrowser` 标题行 **无** `options={run_id}` 形态的 Select；过滤改为 pill 或可读短标签 |

### 2.6 主视图可读性 + command.run 回执（人一眼懂 / Agent 可读）

用户截图（已展开「原始回执字段」）主视线/JSON 仅有：`runId`、`operation_id`、`device_id`、`working_dir`/`cwd`、`receipt.returncode=0`——**没有命令正文、没有 stdout/stderr**。结论：**无论给人还是给机器都看不懂**。

#### 2.6.1 主卡片（默认可见，强制优先序）

| 优先级 | 字段（有则显示） | 来源（payload） |
| --- | --- | --- |
| 1 | 动作名 | `action`（如 `command.run`）→ i18n 短名 |
| 2 | 时间 | `created_at` 本地短格式 |
| 3 | 耗时 | `duration_ms` / `receipt.duration_ms`（有则） |
| 4 | **命令摘要** | `command_preview` 或 `argv` join；过长截断中间省略 |
| 5 | **退出码 + 成功/失败** | `receipt.returncode` + status Tag（0→成功，非 0→失败） |
| 6 | 工作目录 | `working_dir` / `cwd` |
| 7 | stdout / stderr **短摘要** | `receipt.stdout_preview` / `stderr_preview` 或截断后的 `stdout`/`stderr`（默认 ≤240 字 +「展开」） |

无命令字段时：主行显示次要空态「无命令摘要」（**禁止**用 ULID 顶替）。  
无 stdout/stderr 时：不渲染假输出；可显示「无输出摘要」一行。

#### 2.6.2 技术字段折叠（默认收起）

`run_id`、`device_id`、`operation_id`、`event_id`、`context_id`、`job_id`、各类哈希 —— 进「技术字段 / 原始回执」；每项可复制。不占主视线。

#### 2.6.3 根因（代码锚点，已核实 @ main）

设备契约：`command.run` → `{returncode,stdout,stderr,truncated}`（`docs/octopus/device-network-contract.md`）。  
执行端会返回 stdout/stderr；**摘要落库时被白名单丢掉**：

1. `src/octop/infra/execution/events.py` `device_receipt` ~L97–116：`receipt` 只保留 `returncode` 等，**不含** `stdout`/`stderr`；params 只抽 path/cwd 等，**不含** `argv`。
2. `src/octop/infra/devices/service.py` `_record_execution_receipt` ~L1402–1420：同一白名单。

因此 UI **变不出**没有的数据；必须走下方最小补字段，或接受空态。

#### 2.6.4 最小补字段路径（同 PR 优先 / 否则 0020.1c）

**目标 payload 形状（有界）**

```json
{
  "action": "command.run",
  "command_preview": "python -V",
  "working_dir": "...",
  "receipt": {
    "returncode": 0,
    "stdout_preview": "...",
    "stderr_preview": "...",
    "output_truncated": false
  }
}
```

**实现（最小 diff）**

| 位置 | 改动 |
| --- | --- |
| `execution/events.py` `device_receipt` | params：若有 `argv: string[]`，写入 `command_preview` = `list2cmdline`/join，总长 cap **512**；result：除既有键外，允许 `stdout`/`stderr` 各写入 `stdout_preview`/`stderr_preview`（各 cap **2048**，超长截断并 `output_truncated: true`）；**仍可不把全文巨大 stdout 永久塞进 DB** |
| `devices/service.py` `_record_execution_receipt` | 与上同一白名单/预览规则，避免两条写入路径漂移 |
| `RunReceiptBrowser.tsx` | 主卡按 §2.6.1 渲染；预览可展开到 cap 内全文；技术字段折叠 |

**明确不改**：work_mode 证据是否成立的判定逻辑；不把 browser jpeg / 文件 bytes 塞进 ledger（`ledger_result` 原则仍在）。

| ID | 要求 | AC |
| --- | --- | --- |
| REQ-READ-B01 | 主行无密文堆砌 | AC-READ01：未展开时主视线看不到完整 ULID；可见动作名+时间；（有数据时）可见命令摘要与退出码 |
| REQ-READ-B02 | 技术字段可展开可复制 | AC-READ02：折叠区内完整 id 可复制 |
| REQ-READ-B03 | 不删证据 / 不伪造 | AC-READ03：无 stdout 时显示空态而非编造；diff 不改 work_mode 校验 |
| REQ-READ-B04 | 有预览则人机可读 | AC-READ04：补字段后，一次成功的 `command.run` 主卡可见命令摘要 + returncode；有输出时可见 stdout 短摘要 |
| REQ-BACK-B01 | 摘要白名单补预览 | AC-BACK01：新产生的 command.run run_event payload 含 `command_preview` 与（若执行端有输出）`receipt.stdout_preview`/`stderr_preview`；单测或手测一条 argv=`python -V` 可证 |
