# 0048 提示缓存稳定性与任务模型路由

**Status**: In Progress
**Date**: 2026-11-08

## Summary

修复模型请求的动态系统提示造成的缓存失效，并提供账号内按任务设置模型和自动路由。用户确认「各种任务可以人工设置，也可按任务自动选择」。保持现有专家、会话和手动选模入口，使用现有 Python、React、账号设置与提供商目录。

## Context

生产验收会话的 26 次请求使用同一 OpenCode Go DeepSeek 模型。连续请求的 118 个工具定义哈希相同，但 system 首个组件约第 4612 字符处持续变化。差异精确落在会话摘要 provenance.source_revision 和 source_watermarks.activity_revision。每次约 5 万输入 token 仅命中 0 至 1152。

ConversationBriefMiddleware 每次模型调用把实时摘要及版本信息写入 system。WorkModeMiddleware 也把整条运行事件写入 system，跨运行和工作阶段变化会改变前缀。标题和摘要辅助调用没有记录提供商返回的缓存明细。运行轨迹另把已经包含缓存的输入量再次加上缓存量，导致比例偏低。

## Requirements

1. AC01，系统提示只保留稳定说明。会话摘要与工作流状态在最新真实用户消息首次进入模型时快照，后续工具调用和后台摘要刷新不重写已发送的历史前缀。
2. AC02，快照进入 checkpoint 的私有消息元数据，绑定原始内容指纹。模型请求副本重放快照，用户历史仍是原文和附件，不显示内部提示；编辑或压缩内容后不复活旧快照。
3. AC03，权限、执行目标和 Debug 工具写入门禁仍读取实时状态；快照不是授权。需要最新摘要或阶段时通过已有 get_conversation_brief 和 work_step 工具查询。
4. AC04，输入、缓存读写、未缓存输入、输出使用统一口径。缓存比例为缓存读取量除以输入总量；辅助调用也记录缓存字段。缺失数据不能编造命中。
5. AC05，在模型设置内可启用任务路由，分别设置日常对话、编程、推理、资料研究、图片理解、长上下文、标题、摘要与记忆整理的模型。每项支持自动或明确指定账号内可用模型。
6. AC06，聊天手动选模与会话显式固定最高优先。自动模式依据真实附件、工作模式与当前用户文字的可解释规则识别任务，采用任务设置，再沿用专家及账号默认。自动识别不额外调用分类模型。
7. AC07，自动候选只能来自专家所属账号的可用聊天模型；图片与上下文能力来自已有模型目录。无匹配规则时回到现有默认，模型删除或禁用后重新验证。不能跨账号或使用 embedding 模型。
8. AC08，一轮执行确定模型后保持稳定，连续补充和恢复沿用原运行模型。路由不通过重发用户消息实现，也不重放完成的工具。
9. AC09，提供无模型调用的路由预览，显示任务、实际模型和选择原因。实际聊天也展示路由结果，不能只显示一个与执行不符的 AUTO 标签。
10. AC10，账号配置、预览和运行选择隔离，标准 ACP 机器凭据不能访问账号管理接口。已有标题、摘要或记忆的显式模型设置优先于自动规则。
11. AC11，禁用任务路由时保持原有选模行为；现有配置不自动改成其他模型。供应商缓存为尽力而为，验收记录真实返回值，不承诺固定命中比例。
12. AC12，聊天底部只保留紧凑进度和输入区。后台任务收进工具栏，发送方式紧邻发送按钮；默认不暴露脚本、重复提示或空任务分区。完整执行记录、附件、队列、停止和任务管理仍可访问。桌面及窄屏不横向溢出。
13. AC13，结论显示在本轮交付文件之前。纯附件回答和早期片段附件不丢失，重复工具引用不重复展示；图片按真实 MIME 或文件类型直接预览，保留鉴权与点击放大，文件卡提供清晰的预览和下载。
14. AC14，执行设备上的发送文件沿本轮已绑定的执行上下文读取，先核验字节再发布不可变资源，显式专家存储仍使用原后端。保持会话模式和设备读权限门禁，Dashboard 与 IM 都能接收实际文件，失败不推断或推送虚假图片。
15. AC15，图片使用紧凑缩略卡并可点击弹窗细看。交付较多时按图片、文档、表格与数据、代码、压缩包、音视频和其他类型筛选，默认最多展示六项，按需再显示六项；未展示的图片不自动下载预览字节。按用户最新要求不提供交付文件搜索。
16. AC16，Markdown 文件在交付资源、聊天文件面板、工作区、存储浏览、设备文件、知识库与引用、专家配置和子代理文件中默认可阅读渲染，保留源码查看或编辑切换。识别 `.md`、`.markdown`、大小写扩展和 Markdown MIME，切换不丢失未保存草稿。已有技能、人格和分享页渲染继续保留。

## Decision

在应用层捕获动态上下文，固定 Harness 增加通用宿主上下文快照的重放、计数与来源归因。仅在应用层隐藏数据会导致压缩低估长会话预算，因此两者必须随同一个经过验证的固定依赖交付。两类上下文共用内容指纹与消息副本重放工具，各自的实时服务与工具门禁保留。

模型路由复用 SettingsRepo 保存账号 JSON，提供商目录为唯一模型清单。使用确定性的任务匹配与目录能力选择，手动任务模型为偏好规则。自动模式优先保持兼容的现有默认，不根据未知价格或未经测量的速度编造排名。路由无需外部服务或迁移。缓存统计增加迁移 039 的 cache_metrics_reported 标识，保留既有计数，旧账本默认为数据未完整报告；只有全部样本包含真实缓存读计数时显示比例。该字段随实时事件、轨迹、账本及辅助调用保存，明确的零与缺失数据分开处理。

## Value sourcing

| 值 | 来源 |
| --- | --- |
| 缓存读写及输入量 | 统一规范化后的提供商响应 usage |
| 初始摘要 | 当前消息首次使用时 ConversationService.brief 的账号可见结果 |
| 工作流状态 | 当前运行 WorkModeService.begin；后续 work_step 的真实结果 |
| 快照有效性 | 原始 HumanMessage 内容的 SHA256、快照版本 |
| 账号路由规则 | SettingsRepo 的 model_routing.user.{owner_id} JSON |
| 任务类别 | 显式工作模式、附件类型、当前用户文字的固定规则；辅助调用传入明确 purpose |
| 模型能力与可用性 | ProviderStore、effective_provider_models 与现有 context/input/reasoning 字段 |
| 手动优先级 | 当前消息覆盖、会话固定；沿用原入口 |
| 路由解释 | 服务端实际决策的 task/source/reason 字段，由语言包展示 |

## Interfaces and UX

在现有模型设置中增加任务路由面板，提供开关、按任务选模、保存、错误反馈与预览。复用当前表单与响应式布局，显示明确模型 ID 与提供商。聊天保留原模型选择器，AUTO 使用路由；显示本次实际选用模型与原因。

针对用户截图中的底部堆叠，沿用现有玫瑰色主题与字体，用单行进度对齐输入框：中文动作、耗时、进度入口和另开对话。命令正文仅在详情中展示。后台任务成为工具栏按钮，显示活跃数量，抽屉继续提供任务标题、进度、新建和取消。补充当前回答或排队下一轮的切换放在发送旁，提示放入菜单。路由解释使用可展开入口，避免再叠一个常驻状态区。默认输入框更紧凑，保留用户手动拉高能力。

账号接口读取和保存配置，并对当前账号的模型引用校验。预览输入有大小限制，只计算决策，不发模型请求、不改会话、不执行任务。所有接口使用 current_user，遵守机器凭据默认拒绝边界。规则保存失败保留编辑内容。

## Consequences

同一条消息的自动摘要不在工具执行期间悄悄更新，最新事实继续由工具结果和明确查询提供。消息新增时才注入新的摘要快照。保留快照会略增 checkpoint 大小，不保存重复图片字节。

按任务切换模型会影响供应商侧缓存局部性，因此一轮保持模型稳定，自动默认优先沿用兼容模型。手动配置能明确表达用户偏好，自动识别是可解释规则，无法代替完整语义理解。

## Rationale

仅删除摘要版本号仍会因后台重写正文而失效；把动态内容挪到 system 末尾仍在全部历史之前。逐消息快照复用已验证的记忆重放思路，能同时保留历史前缀与当前上下文。配置与执行沿用现有账号和模型解析边界，避免另建凭据或全局模型池。
