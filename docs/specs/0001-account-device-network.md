# 一个 Octop 账号的设备网

Status: In Progress — 用户已授权实现；跨设备与各平台验收仍待证明。
Date: 2026-10-10
Revision: 2 — 多管理端连接、设备工作区和简化启动。
Mode: ENHANCEMENT
Scope: [Octopus 产品计划](../octopus/implementation-plan.md)

## Summary

Windows 运行完整 UI 与管理服务；Linux 只运行无界面的原生设备客户端。
设备可以分别加入多个受信任 Windows 管理端的已有账号，独立保持连接，
不依赖固定主控电脑。Agent 可以指定已授权的设备进行
桌面操作、文件传输和任务执行。Android/iOS 首版作为远程操作端，复用现有页面。

设备加入不要求在每台电脑上创建独立 Octop 用户，也不要求输入 Windows
登录密码。浏览器登录只产生用户会话；控制本机还需要正在运行的原生设备客户端。

## Requirements

- **AC-01 同一身份：** 两台 Windows 使用同一控制中心的已有账号加入，
  得到不同 device_id；设备按 owner_user_id 隔离。已有账号、会话和任务保留。
- **AC-02 注册与在线状态：** 用户明确加入当前设备，设置名称和能力后可见
  平台、连接状态和最后在线时间。客户端断开、重连不会重复注册为新设备。
  单纯打开网页或登录另一个独立 Octop 实例不会自动加入设备网。
- **AC-03 授权与撤销：** 用户选择桌面查看/控制、文件目录读写和命令执行
  的许可。命令执行默认关闭，已有 Agent/HITL 限制继续生效。跨账号、未授权、
  离线或已撤销设备的请求明确失败。撤销阻止新指令并关闭控制连接；正在执行
  的工作请求取消，无法确认停止的工作显示状态未知，不宣称已回滚。
- **AC-04 Agent 定向：** 会话和看板可选择目标设备；Agent 工具使用明确
  device_id。执行记录包含设备、调用者、操作与结果，不因列表顺序改变目标。
  Agent 无法自行增加设备权限；更换任务设备使已确认执行配置失效。
- **AC-05 桌面：** 从控制端选择已加入的另一台 Windows，能够查看画面并
  在授权后操作键鼠；查看权限不能获得输入权限。Linux 在原生主机验证，
  按实际桌面环境报告可用能力，不能将 Windows 成功视作 Linux 成功。
- **AC-06 文件：** 在授权目录之间上传、下载和设备间传输，显示源、目标、
  方向、大小、进度与结果；完成后校验文件内容。路径穿越、符号链接逃逸和
  越权目录请求被拒绝。中断/取消不会将不完整文件报告为完成。
- **AC-07 宿主结算：** 控制中心和设备客户端运行时，关闭网页不停止已提交
  的工作；结果回到控制中心账本。断线/重启先对账，不自动重放无法确认结果
  的桌面动作或命令。设备停止或关机时显示不可用，不声称继续执行。
- **AC-08 凭据：** 每台设备使用独立、可撤销的凭据；设备不保存账号明文
  密码或控制中心 JWT 签名密钥。身份绑定不能仅凭设备名、IP 或客户端传来的
  owner_user_id。凭据不写入日志、URL 或交付包。
- **AC-09 交付：** Windows 先用两台实机证明上述链路；Linux 用原生主机
  验证注册、文件与受支持的桌面能力。Android 先验证同账号远程登录和操作
  Windows/Linux，首版不承诺 Android 本机的后台执行与桌面控制。

## Decision

最新部署优先级（2026-10-10）：用户选择「Win 工位为唯一常开管理端，笔记本和
Ubuntu GPU 为设备客户端，云以后整库再迁」。已确认当前 `10.198.240.130` 是
笔记本，`LJY-Windows` 才是工位。首轮先迁移同一账号/数据实例到工位，接入
三台原生客户端，手机作为浏览器操作端；笔记本关闭后工位与 GPU 仍须可用。
下列 AC-11 多管理端协议保留为可选能力，不是首轮部署的前置条件，也不要求
先完成跨库同步。当前真实状态、切换步骤和未验收项见
[工位部署清单](../octopus/workstation-rollout.md)。此决定不增加已有设备权限。

用户于 2026-10-10 明确选择「任意 Windows 都能管理设备，不依赖当前这台电脑；
Linux 只运行后台客户端」。以下修订取代第一版的单控制中心部署决策：

- **AC-11 多管理端：** 同一个原生客户端可授权并连接多个 Windows 管理端。
  A 关闭后 B 仍可读取授权文件/执行已确认操作；A 重启后身份不变且自动重连。
  每个端点独立凭据、授权、执行器和结果目录；某一端认证失败不能停掉其他端。
  同名用户名不是跨数据库身份凭证，新增管理端必须用其账号的密钥/配对码
  单独授权。页面/命令明确说明各管理端的聊天、项目与账本分别保存。
- **AC-12 设备工作区：** 设备管理页只展示设备、连接、许可和加入方式；桌面、
  文件、命令进入宽屏工作区。工作区保留目标名、返回、能力切换、操作记录；
  权限设置与记录按需打开，不常驻三列挤压桌面。本机终端/浏览器及本机桌面/
  USB 手机作为有明确名称的宿主工具入口，保留已有权限，避免重复导航。
- **AC-13 简化启动：** 已保存连接一键启动全部管理端，不再输入账号密钥。
  首次启动有交互配置入口，添加管理端不覆盖旧身份；支持 Windows 登录后自动
  运行、Linux 用户 systemd 服务，并提供状态/移除入口。自动启动保存路径与
  凭据分离，安装必须由用户明确执行，不自动给设备增加权限。
- **AC-14 隔离与重启：** 一个状态目录只允许一个设备网络进程；防止重复客户端
  互相顶掉。撤销某一端凭据不会复用另一个端的凭据；操作 journal 独立，不
  重放结果未知的命令或桌面动作。关闭派工端会中止其连接上的命令，不能声称
  该命令已迁移到其他管理端继续执行。

复用主动连接协议、DeviceClient、DeviceExecutor 和 Windows/Linux 便携运行时。
新增 network 配置保存端点目录（不复制账号密码、JWT 签名密钥或账号接入密钥）；
保留原 root device.json 作为默认端点，新增端点存于私有子目录。网络运行器隔离
每个连接的失败并持有进程锁；每个执行器拥有独立状态。无需 Linux 入站服务、
新增云中继或 NAT 穿透协议；设备必须能访问各受信任管理端（局域网/VPN/HTTPS）。

现有单端接口与账本仍由该管理端负责；多端管理解决设备控制可用性，不宣称
跨数据库同步全部账号数据。各端必须独立授权且沿用受信任 TLS 验证；显式 HTTP
联调例外仍未加密。直接控制和注册不会经关闭的管理端转发。

用户于 2026-10-09 补充：已有设备可生成密钥，新设备客户端和浏览器均可直接登录。
新增 AC-10：密码/SSO 会话可生成具名、限期 1–365 天的账号密钥，选择浏览器登录
和设备加入用途。明文只显示一次，数据库仅存摘要；撤销/过期使新登录、加入和
该密钥签发的浏览器会话失效。已加入设备凭据单独撤销。密钥会话不能再签发
密钥或配对码。浏览器使用带 key_id 来源的短期 JWT，续期保留来源，HTTP 和
WebSocket 均重新核验有效性；原密钥不放 URL 或日志。客户端可用 --key-file
读取，加入后只保存自己独立的设备凭据，不保存账号接入密钥。

第一版采用单控制中心和主动连接的设备客户端，复用 Python/FastAPI、数据库、
React、已有桌面与文件适配器。第一版设备入口复用 Python 便携运行时，
不为设备网另换技术栈，不以新 Wails 外壳作为完成链路的前置条件。

以下描述保留作为单端协议的兼容设计，多个端点各自运行同一套服务。
初次验收使用现有 Windows 宿主充当一个管理端，这是可更改的部署默认值，
不是要求新增云服务。后续可将同一控制中心迁移到 Linux；账号属于所选控制
中心，多个互相独立的 Octop 数据库即使有同名账号也不会自动合并。

设备向控制中心主动建立独立的设备连接。Browser Hub 继续只承担页面通知；
现有 Bridge 保留独立实例互通用途，可借用其帧编解码、分片、超时和取消逻辑，
但不能将 Bridge 的对端账号登录流程当作设备注册。

## Design

### 用户流程与页面

1. 控制中心保留用户原账号和现有项目、Bot、群聊、任务。
2. 在已登录账号的「设备」页生成一次性配对码；第二台启动客户端，填写
   控制中心地址和配对码。配对码由登录身份签发，将客户端绑定到已有账号，
   避免在 CLI 另做密码/验证码登录或保存账号密码。
3. 用户确认加入当前设备，指定名称、允许能力和文件共享目录。
4. 「设备」页显示名下设备，提供状态、能力、改名、权限、撤销及桌面入口。
5. 对话和看板选择设备；Agent 在该设备许可及自身工具许可范围内操作。
6. 文件传输选择源和目标目录，结果及任务进度在控制中心查询。

「设备」放在现有上下文导航中，不增加一套重复的专家/项目列表。手机页面
使用现有自适应布局。控制中心地址是登录连接配置，不要求设备开放入站 Web 端口。

### 身份与服务边界

- 控制中心持有账号权威、设备注册表、权限和操作账本。账号访问令牌只用于
  认证注册请求；服务端从真实登录用户绑定 owner_user_id。
- 注册后签发高熵设备凭据，服务端仅保存校验摘要，设备端保存在用户权限
  限制的本地凭据文件中；平台安全存储可随后接入。令牌明确限定设备连接
  用途，不能被接受为普通用户 API 登录令牌。
- 配对码高熵、单次使用、10 分钟有效，仅账号本人可签发；服务端从配对码
  记录确定账号，客户端不提供 owner_user_id。服务重启使未使用配对码失效。
- 远程登录与设备通道使用受信任 TLS；局域网开发环境的 HTTP 例外必须显式
  配置，不能因自动发现 IP 而静默降低认证保护。
- 新业务服务放在 infra/devices，数据库迁移及 SQL 留在 infra/db/repos，
  api/routers/devices 只作 typed HTTP/WS 适配，dashboard/src/api 提供封装。
- 设备客户端调用 infra/desktop 的本机采集/输入适配器，文件操作使用
  BackendWorkspace 或同等受根目录约束的适配器。不能直接把已有本机桌面
  API 的 URL 改为另一台机器地址并声称已实现设备路由。
- 每次派发验证用户所有权、设备许可、Agent 许可、确认状态和权限版本；
  客户端同时验证本地授权。服务端和客户端任一侧拒绝均不执行。

### 数据与协议

| 对象 | 权威内容 |
| --- | --- |
| devices | device_id、owner_user_id、名称、平台、凭据摘要、权限版本、撤销时间、最后在线时间 |
| device_grants | 允许能力及读写根目录；区分桌面查看/输入，版本随授权变化 |
| device_operations | operation_id、用户/Agent/任务、device_id、类型、确认版本、时间、状态和结果摘要 |
| file_transfers | transfer_id、源/目标设备及授权根、大小、校验值、已确认进度和结果 |

具体表字段随实现迁移确定，不能复用 bridge_connections.owner_user_id 推断
设备账号映射。客户端声明能力表示平台可用性，用户授权决定能否执行。

设备通道携带协议版本、device_id、连接代次、operation_id 和权限版本，支持
认证、心跳、派发、确认、进度、结果、取消及流传输。重连替换旧连接，旧连接
不能继续领取新操作。非文件控制消息与大文件/画面分片分开限流，避免传输
阻塞撤销与取消。所有执行响应绑定操作 ID，禁止按最新会话猜测归属。

桌面画面经设备通道中继到有权控制的用户会话，输入只发往选定设备。
共享目录以设备实际路径解析并拒绝逃逸；写入临时文件，校验后提交目标文件。
首版传输由控制中心中继，避免要求设备互相连通。大文件断点续传作为后续
增强；首版中断明确失败，可手动重试，不能据此宣称已实现续传。

### 生命周期和任务账本

设备连接服务由宿主运行，与页面生命周期分离；是否安装开机服务由用户配置。
注册记录和操作状态持久保存，活跃连接只存在内存。任务关联设备操作，沿用
现有独立验收和父子完成条件。换设备触发重新确认，不复制另一个独立实例的
任务账本作为权威。

连接丢失时工作结果保持未确认；重连查询客户端保存的操作结果。执行器以
operation_id 去重，控制中心与客户端均不能盲重试已开始的动作。重启丢失
可核实证据时标记 interrupted/unknown，要求明确重试。

## Build plan

1. 设备身份、注册/撤销服务和专用凭据；所有权与用途隔离测试。
   对应 AC-01、AC-02、AC-03、AC-08。
2. Python 设备连接入口、心跳/重连/对账与客户端本地许可；两台 Windows
   同账号注册实测。对应 AC-02、AC-03、AC-07、AC-08、AC-09。
3. 设备页及桌面目标路由，复用采集/输入；证明查看权限与控制权限的区别。
   对应 AC-03、AC-05、AC-09。
4. 授权目录文件中继、进度/取消/校验和两台实机往返传输。
   对应 AC-03、AC-06、AC-09。
5. Agent 工具和看板目标设备、确认失效、结果与账本关联；关页面、断线、
   撤销和重启实测。对应 AC-03、AC-04、AC-07。
6. Linux 原生和 Android 远程端验证，按实际平台能力提供交付与限制。
   对应 AC-05、AC-06、AC-09。
7. 多端点运行器、单进程锁与添加/列举管理端；双管理端关闭一端仍可读取文件、
   单端拒绝连接不影响另一个端，保留旧 state 重连（AC-11、AC-14）。
8. 设备管理与操作工作区分开，宿主工具归位；宽桌面/手机检查（AC-12）。
9. 首次配置、一键重连与明确的自动启动安装/移除；Windows 登录任务与 Linux
   systemd 模板验证。真实 Linux 开机测试未运行必须标明（AC-13）。

每步用真实行为证据更新交付记录。不能以规格、静态页面或同一宿主上的
两个浏览器会话代替跨设备验收。

## Consequences / Follow-up

### 2026-10-11: AC-13 首次接入简化

用户暂缓 Windows 自启动安装，要求缩短首次接入。无参数运行同一个
`start-device.bat` / `start-device.sh`：已有身份直接按保存权限重连；首次启动
询问管理端地址、名称、权限方案和共享目录，在完整权限确认后隐藏输入一次性
配对码或设备接入密钥，保存独立身份并立即连接。Linux 不提供桌面权限方案。
远程 HTTP 必须单独确认；拒绝授权不登记设备或创建共享目录。该入口不安装
启动任务或服务。原有显式参数接入、添加管理端和自动启动命令继续保留。

- 可复用现有业务栈和本机操作能力，但需要新增设备身份、连接和调度层。
- 便携包同时包含控制中心和独立设备客户端入口。第二台电脑使用
  start-device.bat/start-device.sh 加入，无需启动另一套账号数据库。
- 用户可明确安装或移除 Windows 登录任务、Linux systemd 用户服务；原生开机
  验收仍待进行。断点续传和直接设备间传输可继续增强。现有 Bridge 连接保留。
- 第二台 Windows 已实测共享目录读取和桌面画面；Ubuntu 20.04 原生文件/命令、
  双管理服务断开/恢复、独立撤销已实测，用户级服务 installed/enabled/active 且
  Linger=yes。两个测试管理服务在同一 Windows 主机，实体双管理电脑切换、两种
  OS 机器重启和手机真机仍待验收，不将规格标记为 Accepted 或全部验收。

实现接口与并行文件所有权见 [开发合同](../octopus/device-network-contract.md)。
