# 0047. 持续对话与回答恢复

**Date**: 2026-11-07
**Status**: In Progress

## Summary

聊天过程中可以继续补充文字和文件，后台工作和输入框独立。模型暂时繁忙时显示等待和恢复状态。重试恢复原回答，沿用已有消息、附件和已完成工具结果。

## Context

当前重试按钮调用普通发送入口，追加一条重复用户消息。模型重试缺少可见进度，余额不足可能被误判为限流。上传中的文件阻塞文字发送，发送后还可能被清除。

## Requirements

* **AC-1**：重试使用原检查点，不追加用户消息，不重放已完成的工具。历史状态变化后拒绝旧重试。
* **AC-2**：同一恢复命令只能启动一次。并发、断线和取消不能制造第二次执行。
* **AC-3**：短暂限流、网络和服务错误采用有上限的退避，显示真实等待截止时间和尝试次数。认证、余额、权限和输入错误立即给出处理入口。
* **AC-4**：运行中可直接补充文字，明确区分补充当前回答与稍后发送。含文件的输入保持可靠排队回执。
* **AC-5**：上传逐文件进度、取消和重试保留；文字发送不取消尚未完成的上传，成功发送只移除本条使用的附件。
* **AC-6**：中文状态条持续显示阶段和已用时间，未知阶段使用中文通用文案，详细思考内容可折叠。
* **AC-7**：成果沿用授权资源卡，支持预览、下载和可访问的文件信息。
* **AC-8**：执行中的工具展示中文动作、可理解的目标和实际结果状态，原始参数和英文日志收进技术详情。摘要只依据真实输入和回执，不生成虚构进度。
* **AC-9**：后台执行任务在会话摘要、任务列表和详情中展示可理解的名称、动作、状态、最近观测时间及日志入口。任务编号仅在技术详情中显示。没有任务说明时明确使用通用名称，不把哈希编号当成标题。

## Options considered

继续发送同一文本实现容易，但会重复用户消息并可能重复工具。重写运行引擎范围过大。选择现有 Harness 检查点、取消和 steering 机制上的窄恢复入口。

## Decision

在现有 FastAPI、React、LangGraph 与 run_events 上修复。只恢复明确失败且待执行节点为 model 的检查点；无法证明安全时明确拒绝，绝不退回普通发送。现有已完成工具结果由检查点保留。恢复操作经原线程锁并复核权限、执行上下文和最新检查点。

## Feature design

恢复凭据存于 run_events 的 chat_response 记录，记录 owner、agent、thread、当前检查点、恢复检查点和白名单请求配置，不保存消息正文或凭据。命令回执使用 chat_retry，command_id 幂等。

| 接口 | 输入 | 输出 | 权限 |
| --- | --- | --- | --- |
| GET /agents/{agent}/threads/{thread}/response-recovery | 线程 | 最新可恢复回答及当前状态 | 原账号与线程 |
| POST 同路径 | command_id、response_id、可选 model | 原回答恢复流 | 同上，复核检查点、模型及当前执行权限 |

| 显示值 | 来源 |
| --- | --- |
| 等待截止时间 | 服务端 Retry-After 或配置的指数退避 |
| 尝试次数 | 当前模型调用的重试循环 |
| 重试目标 | 服务端持久化 response_id 与检查点 |
| 阶段 | Harness run_phase 与工具事件 |
| 已用时间 | 当前 turn 开始时间 |
| 文件状态 | 每个实际上传请求及服务端注册回执 |
| 成果 | 已授权不可变 resource_id/version |
| 工具动作和目标 | 现有工具名称的本地化词条、已脱敏的实际参数及现有审批摘要规则 |
| 工具结果 | 实际工具输出、错误字段、退出码和已返回的文件/资源信息 |
| 后台任务名称 | 同一 owner/agent/thread/context/job 的确切提交回执和任务说明，缺失时使用本地化通用名称 |
| 后台任务状态 | run_events 的真实状态、updated_at 和既有45秒观测过期规则 |
| 日志入口 | 现有受权限控制的 execution jobs.logs，保持原始日志可查看 |

状态为 running、waiting_retry、retrying、completed、failed、cancelled。取消中和已取消分别呈现。旧错误不凭文字猜测恢复位置。

替换模型时沿用原检查点，重新验证模型授权，不沿用旧模型专属的思考参数。恢复后的新工具、审批、用量、历史记录和账号通知沿用已有服务。恢复过程中补充消息遵守已有安全边界，末尾才被接收的补充从最新结果继续。

## Build plan

1. 实现模型错误分类、退避提示和安全恢复入口，验证 AC-1、AC-2、AC-3。
2. 连接回答恢复通知、中文运行状态和补充输入，验证 AC-1、AC-3、AC-4、AC-6。
3. 分离文字发送与上传生命周期，完善成果展示，验证 AC-5、AC-7。
4. 运行前后端检查并在浏览器验证桌面与移动布局，覆盖 AC-1 至 AC-7。

## Consequences

已有终态旧记录若没有安全恢复凭据，会明确提示无法恢复。恢复会读取检查点并写入少量运行回执；不引入新服务或数据库迁移。
